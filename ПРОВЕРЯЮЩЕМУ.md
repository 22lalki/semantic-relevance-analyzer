# Шпаргалка проверяющему

Инструмент разбивает страницу на пассажи, скорит каждый против целевого запроса по векторной близости и показывает, какие секции вытянут страницу в AI-поиске, а какие — мёртвый груз.

---

## Запуск (30 секунд)

```bash
npm install
npm run dev          # http://localhost:5173
```

Ключи **не нужны**. `npm run dev` поднимает и фронт, и serverless-функции из `api/` — отдельный `vercel dev` не требуется.

```bash
npm run build        # tsc -b (3 проекта) + vite build
npm run lint
```

## Что посмотреть за 2 минуты

| Шаг | Действие | Что проверяется |
|---|---|---|
| 1 | **Try demo** → **RUN SEMANTIC ANALYSIS** | Весь цикл в один клик, все 3 блока результатов |
| 2 | Навести на точку карты, кликнуть | Тултип + скролл к нужной строке таблицы |
| 3 | Навести на точку графика | Кастомный тултип с полным заголовком |
| 4 | Клик по строке таблицы | Аккордеон с полным текстом пассажа |
| 5 | **Download CSV** / **Copy** | Выгрузка и буфер обмена |
| 6 | **GENERATE AI ANALYSIS** | Блок 3 без ключа (жёлтая плашка) |
| 7 | Таб **Compare** → Try demo → Run | Два ряда на графике, вердикт, переключатель A/B |
| 8 | Таб **URL** → любая публичная статья → Fetch | Реальный фетч, «Ready: N chars indexed» |
| 9 | Ширина окна 375px | Адаптив: карта в столбик, таблица скроллится |

**Проверить URL-фетч можно на** `https://en.wikipedia.org/wiki/Accountant` — 19 заголовков, ~27k символов.

## Ключ API — три состояния

Поле **AI API Key** на форме:

| Что ввести | Что произойдёт | Плашка |
|---|---|---|
| *пусто* | Разбор считается локально по вашим же баллам | жёлтая |
| `test` | Прогоняется **весь живой код-путь** (запрос → разбор JSON → нормализация → рендер), но модель не вызывается | синяя |
| настоящий `sk-ant-…` | Реальный вызов Claude | нет |

`test` добавлен специально для проверки: он позволяет увидеть живой путь и состояние загрузки, ничего не потратив. Текст в нём — заглушка, и плашка об этом прямо говорит.

## Как считается балл (коротко)

**Режим A — Fast Mapping (lexical), по умолчанию, без ключа.**
TF-IDF по стеммированным униграммам и биграммам. Три сигнала: покрытие буквальных слов запроса (BM25), покрытие тематического словаря самой страницы (с поправкой на то, насколько страница вообще про запрос), покрытие биграмм.

> **Честно:** это сравнение **слов, а не смысла**. Два абзаца об одном и том же разными словами получат разные баллы. В интерфейсе режим так и подписан. Веса и калибровка 0–100 — именно калибровка, подобранная на демо-статье, живой странице Википедии и заведомо нерелевантной контрольной странице (она корректно даёт 0).

**Режим B — Embedding-based.** Настоящие векторы через `/api/embed`, косинус. Если эндпоинт не настроен — **не падает**, а откатывается на лексический режим и объясняет почему.

Пороги: ≥65 зелёный, 43–64 жёлтый, 0–42 красный.

## Что стоит знать заранее

- **Без единого ключа приложение полностью рабочее** — это было требованием ТЗ и проверялось отдельно.
- **Оффлайн-разбор слабее живого** и не умеет главного: назвать сущность, которой на странице нет («не упомянут HMRC»). Для этого нужна модель со знанием предметной области. Локально измеримо только то, что уже написано.
- **Живой вызов Claude** проверен на невалидном ключе (корректный 401 с человеческим сообщением) и через мок. С настоящим ключом я его не прогонял — своего ключа у меня нет.
- **Модель** `claude-sonnet-4-6` как в ТЗ, но вынесена в `ANTHROPIC_MODEL` — меняется без передеплоя.
- Второй референс (сравнительная карта конкурентов Хинкли) **не реализован** — по ТЗ и не требовалось; как расширять, описано в README.

## Переменные окружения (все опциональны)

| Переменная | Что включает |
|---|---|
| `ANTHROPIC_API_KEY` | Живой Deep AI Analysis и автозаполнение Semantic Context |
| `ANTHROPIC_MODEL` | Другая модель (по умолчанию `claude-sonnet-4-6`) |
| `EMBEDDINGS_API_KEY` | Режим Embedding-based |
| `EMBEDDINGS_API_URL` | OpenAI-совместимый базовый URL |
| `EMBEDDINGS_MODEL` | По умолчанию `text-embedding-3-small` |

Полное описание архитектуры и скоринга — в [README.md](README.md).
